# 3. Target Users & User Needs

## Maya — Mobile Regular

**Context:**  
visits the website from her phone while she is already out.

**Primary goal:**
looking for cafe information to make sure her usual is still currently available.

**Important information/tasks:**
store information such as menu, location and hours

**Likely friction:**
menu information is difficult to scan on a small screen.

**Design/accessibility implication:**
Scannable text, with predictable navigation.

## Daniel — Hill Country Visitor

**Context:**
New visitor, searching for a local coffee shop.

**Primary goal:**
Current information about the location, to make sure that it'll fit properly into his planned day.

**Important information/tasks:**
Values, accessible menu, informative pictures and descriptions.

**Likely friction:**
unclear information

**Design/accessibility implication:**
All pages should be easily understandable no matter the page.

## Renee — Deliberate Planner

**Context:**
Visits cafes based on reviews of locations.

**Primary goal:**
Reviews website for useful information, and the atmosphere of the location.

**Important information/tasks:**
Menu and Values,

**Likely friction:**
broken layout from increased text size, tiny images/documents, and "click here" links.

**Design/accessibility implication:**
flexible layout, text that remains usable when enlarged, and descriptive links.

# 8. Accessibility Requirements

Define accessibility requirements before design/development begins.

At minimum, address:

## Semantic Structure

Proper Navigation, followed by the main content of the page, with a footer featuring store information.

## Heading Structure

Logical Headings that match the navigation, with sub headings for its provided information. for example, in menu a sub heading could be "Hot Coffee" followed by a "Cold Coffee" heading for the next section.

## Keyboard Access

Make sure all information is accessable with keyboard controls, and buttons/Navigation allows keyboard to use them.

## Visible Focus

Allows Keyboard to be visible on the webpage. This could be with an outline, or changing the color of elements that it has current access to.

## Color Contrast

Contrasting colors when it is currently being accessed.

## Images / Alternative Text

informative alternative text featured for provided images. Hours, location and prices will stay strictly text.

## Links & Buttons

links will be used in navigation, any links included will provide a use clear label for the link.

## Responsive Reflow / Zoom

Keep content and controls usable when text is enlarged or the viewport is narrow.

## Interactive Components / Forms

Menu is required, I could use it as a form, so its easily editable by the client. it would also be helpful incase the client hope to add online ordering in the future.

## Accessibility QA

[How will accessibility be checked before final delivery?]
we will include keyboard controls, alt text and clear labeling. afterwards we will double check the website with multiple accessability checkers to make sure it meets standards.
